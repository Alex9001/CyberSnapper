Visual baselines

Promote trusted captures, compare every new run, set sensitivity and allowed-difference thresholds, then inspect side-by-side, overlay, or generated diff views.

⌁

Three real engines

Run Chromium, Firefox, and WebKit through Playwright. Select only what matters for a quick check or fan out for broad coverage.

◷

Schedules that persist

Once, interval, daily, weekly, and monthly recurrence with IANA time zones. The background agent owns the queue so the window does not need to stay open.

⌘

Automation included

The native CLI and authenticated localhost API share the same projects, queue, artifacts, and history as the GUI. No parallel universe to reconcile.

Output that fits the job

Full page, viewport, or CSS element captures in PNG, WebP, AVIF, and Chromium PDF—with collision-safe naming and portable output folders.

A workflow you can trust

From URL to signal in three steps.

  1. 01

    Define the capture

    Add URLs, choose browsers and viewports, then tune page settling, selectors, formats, and naming in a reusable profile.

  2. 02

    Run now or later

    Start from the UI, submit through the CLI or API, or attach the profile to a recurring schedule. Every request enters one durable queue.

  3. 03

    Review the evidence

    Browse history, open artifacts, establish baselines, and focus on visual changes above your project’s acceptable threshold.

Local-first architecture

Your captures remain your files.

Projects are ordinary portable folders backed by SQLite. The Qt interface talks to a local background agent; a private Playwright worker drives browsers only when a capture runs.

  • No hosted account or cloud dependency
  • API binds only to 127.0.0.1 and is off by default
  • Private-network navigation protections and pinned DNS resolution
  • Readable project manifest, captures, baselines, and diffs
