# CyberSnapper 2.3.3 (2026-08-23)

CyberSnapper 2.3.3 fixes a Chromium capture regression and makes browser and
background-service state trustworthy after an update.

## Chromium capture reliability

- Fixes an unhandled `EPIPE` in the DNS-pinning filtering proxy when Chromium
  closes an HTTPS CONNECT tunnel while data is still in flight.
- Handles errors and closure symmetrically on both sides of CONNECT and
  WebSocket tunnels instead of allowing a normal browser disconnect to
  terminate the capture worker.
- Cleans up aborted proxied HTTP requests and response streams without weakening
  private-network blocking or DNS pinning.
- Adds a regression test that repeatedly drops active CONNECT tunnels while the
  destination is sending data.

## Browser installation status

- Consumes browser completion protocol events from either stdout or stderr and
  drains both process channels before deciding the worker result.
- Prevents machine-readable protocol JSON from appearing in the native UI or
  expandable installer logs.
- Ends successful operations with a concise installed-and-ready message and
  ends failed operations with a real terminal failure state.

## Update compatibility

- Detects when a newer GUI or CLI encounters an older background agent.
- Replaces an idle older agent with the packaged version automatically.
- Never interrupts active capture jobs or browser operations; a busy mismatched
  agent is reported clearly and must finish before the application is reopened.
- Prevents an older CLI from replacing a newer running agent.

## Verification

- A real Chromium capture completed desktop, tablet, and mobile outputs through
  the proxy path that previously crashed.
- Worker typechecking and all 36 worker tests pass.
- Native core, GUI, and CLI tests pass.
- Release packages are smoke-tested with browser installation and real capture
  on Linux, Windows, and macOS for x64 and arm64 before publication.
