# CyberSnapper 2.3.2 (2026-08-22)

CyberSnapper 2.3.2 makes managed browser installation reliable and visible
across the native application and packaged releases.

## Browser installation

- Fixes Playwright CLI discovery inside packaged applications, including the
  AppImage layout that previously could not start an on-demand download.
- Shows live component progress, percentage, elapsed time, queue position, and
  expandable installer output in Settings.
- Runs only one browser installation or verification at a time and queues
  additional engines predictably.
- Supports cancellation from the GUI and CLI. Closing the GUI during an active
  operation explains the consequences and defaults to keeping the app open.
- Verifies a real headless launch before an engine is marked ready for capture.

## Diagnostics and automation

- Distinguishes a downloaded engine from one that can launch. Missing host
  libraries produce a `downloaded_unavailable` result while preserving the
  downloaded files.
- Lists exact missing shared libraries and, on supported Debian and Ubuntu
  systems, provides a dependency command for the user to review and run.
  CyberSnapper never invokes a privileged package manager automatically.
- Adds `cybersnapper-cli browsers status`, `install`, `verify`, and `cancel`,
  including wait mode and Ctrl+C cancellation.

## Packaging reliability

- The package smoke test now invokes the packaged browser installer and launch
  verification before running a real three-viewport Chromium capture.
- Detached CLI agent startup explicitly disconnects standard input and output,
  preventing package automation from waiting indefinitely on inherited handles.
- Worker, native, GUI, queue/cancellation, and packaged-capture regressions cover
  the complete installation path.

WPEWebKit and libproxy-webkit are not added as alternate capture engines in
this release; CyberSnapper continues to use Playwright's Chromium, Firefox, and
WebKit builds so capture behavior stays consistent across supported platforms.
