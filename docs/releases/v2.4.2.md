# CyberSnapper 2.4.2 (2026-10-02)

## AppImage updates and discovery

- Linux x64 and arm64 AppImages embed separate stable GitHub release channels for AppImageUpdate-compatible external tools.
- Each release includes a matching `.AppImage.zsync` sidecar, covered by SHA-256 checksums and provenance alongside the existing twelve native packages.
- Desktop/AppStream metadata includes the release identity, screenshots, categories, and the catalog-compatible appdata filename.
- Existing package filenames and download links stay the same. Images older than 2.4.2 need a one-time manual upgrade before external update tools can use the new channel. Close CyberSnapper before updating.

Catalog readiness is tested independently; a successful package build does not mean the upstream catalog submission has been accepted.

## Stronger dependency and release checks

- Dependabot groups security and production/development patch/minor updates separately; major updates stay individual for review. Automatic merging is not enabled.
- CI enforces strict dependency engines and a consistent lockfile, Node.js 20.9.0 compatibility, required browser coverage, and Linux/Windows/macOS native checks.
- Release checks validate update channels, sidecar metadata and block checksums, and actual offline zsync reconstruction.
- The exact x64 candidate is checked on Ubuntu 22.04 and 24.04 without a Qt SDK and run through the pinned upstream AppImageHub worker before release assembly.
- Assembly fails on missing, unexpected, empty, or mismatched assets and preserves a complete checksummed rehearsal bundle.

All six platform/architecture package jobs retain end-to-end capture smoke tests. macOS remains ad-hoc signed and not notarized; Windows and Linux packages remain unsigned.
